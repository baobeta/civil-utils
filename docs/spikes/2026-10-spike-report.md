# Spike report — Civil 3D 2021 API (PRD §10)

Civil 3D build tested: **13.3.854.0** (Civil 3D 2021 update 2021.3; AutoCAD API 24.0.47.0), from the installed product registry and the live 2021 process.

| # | Question | Method | Result | Decision |
| --- | --- | --- | --- | --- |
| 1 | Bundle loads on Civil 3D 2021, not on plain AutoCAD 2021 | Task 11 step 7 | **Pass for Civil 3D and a standalone plain-AutoCAD control; exact-version control limitation noted.** CI run 35981495481 installed with `install.cmd`; Civil 3D 2021 returned the expected `C3DTools 0.1` / `Km1+234.50` message. `uninstall.cmd` removed the bundle and a Civil restart reported `Unknown command "CTHELLO"`. The installed 2021 executable launched with `/product ACAD` still loaded AEC Base and is therefore a shared Civil installation, not a valid plain control. The genuinely standalone AutoCAD 2022 installation reported `Unknown command "CTHELLO"`. | Accept Civil-only loading for the tested standalone host. Keep `Platform="Civil3D"` and R24.0 pinning. Exact plain AutoCAD 2021 was not independently installed; the shared 2021 Civil executable is not a valid substitute. |
| 2 | Preview + single undo with COGO points and alignments | Temporary `CTSPIKEALL`/`CTSPIKECOUNT`: add a point, lightweight polyline and `Alignment.Create(...)` in a transaction, abort it, then apply the real fixture in one committed transaction. | **Pass.** The aborted preview left counts unchanged at alignments 0, COGO 0. The committed fixture produced alignments 1 and COGO 3. One `U` restored alignments 0 and COGO 0; surfaces also returned from 2 to 0. | Keep the preview/apply pipeline. Preview is non-destructive; apply is one transaction and one undo. |
| 3 | Alignment from polyline with arcs; profile from surface; profile view | Create a lightweight polyline with a non-zero bulge, then call `Alignment.Create`, `TinSurface.AddVertices`/`Rebuild`, `Profile.CreateFromSurface` and `ProfileView.Create`. | **Pass with signature correction.** One arc survived alignment creation. The surface profile and profile view were created; profile elevation at station 62.21441469 was 0. In 2021, `ProfileView.Create` takes the **alignment** plus band-set/style IDs, not a profile ID as the plan implied. | Use the verified 2021 signatures. C-03 can create alignment/profile/view from a generated surface without a manual conversion step. |
| 4 | Sample line at a given station | Feed `StationPlanner.Build(0,100,25,null)` into `Alignment.PointLocation(station, ±10)` and `SampleLine.Create(name, groupId, Point2dCollection)`; inspect the station overload. | **Pass.** Point-based lines were created at stations 25, 50 and 75 with ±10 m offsets. Reflection also confirmed `SampleLine.Create(string, ObjectId, double)` exists in 2021. | Implement the station overload when its default offsets fit; retain the tested point-based route for explicit offsets and as fallback. C-06 stays in MVP. |
| 5 | Material section areas per station; own volumes vs Civil 3D volume report | Create two TIN surfaces, sample lines and section views; call `QTOMaterial.Add(surfaceId, code)`, inspect section IDs/QTO results, and compare `AverageEndArea.Compute` with Civil 3D QTO. | **Partial.** `QTOMaterial.Add(ObjectId,string)` in 2021 requires a **Corridor**, not a Surface. Without a corridor/compute-materials mapping, `GetSectionIds()` remained empty; per-material areas and a QTO comparison were unavailable. Volume Report XML is not exposed by the managed API, so maximum difference is **N/A**. The core average-end-area calculation remains usable. | Move automatic per-material volume comparison in C-07 to **P1**. For MVP, use available section geometry/imported station data; do not promise material-by-material Civil 3D report parity until a corridor fixture or supported report path is proven. |
| 6 | Pipe diameter, inverts, slope; structure rim/sump | Inspect the live 2021 `Pipe`/`Structure` API and attempt to build a network from the default parts list. | **Partial.** `Pipe` exposes `InnerDiameterOrWidth`, `OuterDiameterOrWidth`, `Length2D`, `StartPoint`, `EndPoint` and `Slope`, but no `WallThickness`; derive wall as `(outer-inner)/2`. `Structure` exposes `RimElevation`, `SumpElevation` and indexed pipe wall/invert-depth data. The default metric parts list exposed families but no usable part size, so no live pipe/structure instance was created and `StartPoint.Z` centerline-vs-invert semantics remain unverified. | Keep C-08 conditional on a real project network. Use derived wall thickness. Add a project-network fixture to Plan 2 and verify endpoint Z semantics before locking cover/invert calculations. |
| 7 | XLSX with Vietnamese text; AutoCAD Table | In the Civil 3D `net48` process, create an AutoCAD `Table` and try ClosedXML 0.105.1 with Vietnamese headers. | **Partial.** The AutoCAD table was created successfully. The 2021 public API has no `TableData` type; direct table sizing/text methods work. ClosedXML failed during workbook initialization because `SixLabors.Fonts` requested `System.Numerics.Vectors, Version=4.1.3.0`, which was not available in the Civil process. | Keep direct AutoCAD `Table` creation. Move XLSX export to P1 until a compatible/merged dependency set or supported resolver is proven; do not ship ClosedXML 0.105.1 unchanged. |

## Scope changes for C-01…C-08

- **C-07 (`CTKHOILUONG`):** automatic per-material comparison with Civil 3D moves to **P1**. The 2021 managed API ties `QTOMaterial.Add` to corridors and does not expose a surface-only material mapping or Volume Report XML.
- **C-08 (`CTCONG`):** remains in MVP, but wall thickness must be derived from outer/inner diameters. Plan 2 must verify `StartPoint.Z` and invert mapping with a real project pipe-network fixture before implementing cover/invert checks.
- **XLSX portion of table/export work:** moves to **P1** until the `System.Numerics.Vectors` binding conflict is resolved. Direct AutoCAD tables remain available.
- Alignment/profile/view and sample-line generation remain in scope using the verified 2021 signatures above.
- Preview/apply/single-undo behavior is accepted for commands that create Civil objects.
